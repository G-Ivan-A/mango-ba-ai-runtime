# Цель шага и «Итог шага» для БА (SSOT, issue #490)

Единственный источник трёх вещей для каждого шага BCREQ этапа 1:

1. **Цель** — карточка шага на сайте (раздел «Процессы»): как работает промпт
   и зачем его применяют. Заменяет колонку «Что делает БА» в карточках
   тестового набора (п. 1.1 issue #490).
2. **Результат и проверка БА** — под «Результатом» карточки: обязательна
   ли проверка БА и что проверить; технический шаг можно не проверять
   (п. 1.1).
3. **Блок «Итог шага»** и блок **«На согласование БА»**, которыми модель
   заканчивает каждый ответ (п. 1.2, 1.3).

Из этого файла собираются:

- блок «## Итог шага для БА» в 24 промптах AIN
  ([`scripts/build_bcreq_a_in.py`](../../scripts/build_bcreq_a_in.py));
- тот же блок в черновиках Ш-ХХ
  ([`scripts/build_bcreq_step_prompts.py`](../../scripts/build_bcreq_step_prompts.py))
  и в системных Ш-А, Ш-1, Ш-2
  ([`scripts/build_bcreq_system_track.py`](../../scripts/build_bcreq_system_track.py));
- `site/data/step-handoff.json` — цель и проверка для карточек и блок для
  опубликованных промптов Ш-В и Ш-С: их файлы `prompts/` заморожены как
  архив этапа 1, поэтому сайт добавляет блок к копируемому тексту, а сам
  файл не меняет ([`scripts/bcreq_handoff.py`](../../scripts/bcreq_handoff.py)).

Правка цели, проверки или шаблона — только здесь, затем пересборка:
`python3 scripts/bcreq_handoff.py && python3 scripts/build_bcreq_a_in.py &&
python3 scripts/build_bcreq_step_prompts.py && python3 scripts/build_bcreq_system_track.py &&
node scripts/generate-pages-data.mjs`.
Проверка согласованности — `python3 scripts/validate_issue_490_step_handoff.py`.

## 1. Правила

| ID | Правило |
| --- | --- |
| ИШ-1 | «Итог шага» идёт после результата, receipt и «На согласование БА» (если есть); в промптах с маркером `КОНЕЦ` — перед ним. «Состояние BCREQ» на гейтах и точках памяти входит в результат. Правило ЧТ-3 («вопросы в конце») это не нарушает: итог — не результат и не вопрос. |
| ИШ-2 | Первая строка итога — «Выполнен промпт <ID> «<название>»: <что сделала модель>», одна фраза, без самооценки. |
| ИШ-3 | Вторая строка — по колонке «Проверка БА»: `обязательна` — «БА — проверить: …»; `технический` — «Шаг технический, можно проверить (…), но не обязательно. ИИ-ассистент ожидает ввода промпта <следующий> без обязательного согласования БА выполненных действий». |
| ИШ-4 | Технический шаг: ввод БА следующего промпта — явное принятие текущей версии результата. Для AIN-06 и AIN-22 после успешного «Итога шага» молчание означает принятие текущей версии при отсутствии возражений. Действие следующего шага требует отдельного вызова. Остальные технические шаги принимаются вводом следующего промпта; гейты Г-IN, Г-С1, Г-W, «Выпуск» и AIN-21 техническими не бывают. |
| ИШ-5 | Если в ответе есть положения, которые БА должен явно согласовать, перед итогом идёт блок «На согласование БА»: нумерованный список простыми словами, без таблиц, кодов и служебной разметки; в пункте — что принять и как ответить («согласовать» или «исправить: …»). Техническая разметка выше остаётся, блок её дублирует для человека. |
| ИШ-6 | На техническом шаге блок «На согласование БА» выводится, только если появился блокер или конфликт норм; тогда вторая строка итога — «БА — проверить: …» с конкретным действием. Обычный пробел БЗ не выносится на согласование. |
| ИШ-7 | Шаг не выполнен (blocked, rework, нет входа) — вместо второй и третьей строки: «Шаг не выполнен: <причина>. БА — <что дать или к какому шагу вернуться>». |
| ИШ-8 | Формат шагов (системный или декомпозированный) выбирает БА на сайте; модель его не спрашивает. Следующий промпт берётся из колонки «Следующий» для формата из «Состояния BCREQ»; без записи — декомпозированный. |

AIN-01…AIN-24 ([маршрут](bcreq-a-in-route.json)).
