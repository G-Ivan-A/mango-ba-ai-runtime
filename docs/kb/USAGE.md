# Как искать сведения в локальной БЗ

`docs/kb` — уровень `ST-5-LOCAL` из `taxonomy/source-tiers.yaml`. Перед
локальным поиском примените доступные уровни источников в порядке, заданном
маршрутом. Навигационные метаданные помогают выбрать источник; фактом служит
только цитата из открытого раздела с локатором.

## Поиск без чтения всей БЗ

1. Откройте только [`MAP.json`](MAP.json). Сопоставьте тему вопроса с `title` и
   `aliases` документов и, если продукт уже известен, с `product_ids`.
2. Сначала откройте `sections_toc` одного или нескольких подходящих документов:
   оглавление читается за одно обращение и содержит все разделы документа.
   Это текст UTF-8: строка заголовка `section`, `title`, `file`, затем по строке
   на раздел; поля разделены табуляцией, кавычек и экранирования нет. Выберите
   разделы по `title`, прежде чем читать их текст. `file` — имя файла в каталоге
   `sections/` рядом с `index` этого документа: у `speech-analytics--kats` это
   `docs/kb/speech-analytics/kats/sections/<file>`.
   Строку `sections_map` открывайте, только когда нужны подсказка `hint`,
   страницы или токены: карта большого документа за одно обращение не читается.
   Записи карты идут в порядке оглавления и занимают по 9 строк, поэтому без
   поиска запись N-го раздела читается диапазоном строк карты от `9N-1` до `9N+8`.
3. Прочитайте файлы выбранных разделов. Если нужен контекст, откройте соседний
   раздел из того же оглавления или `index.md` документа. Цитируйте источник по
   его `source_refs`, номеру страницы и пути раздела. Подсказка карты сама по
   себе не подтверждает продуктовый факт.
4. Если ответа нет, выполните `navigation.retrieval_if_insufficient` в
   указанном порядке: другие разделы документа → другие документы группы →
   документы с общим `product_ids` → весь каталог. Если локальный корпус
   по-прежнему не даёт доказательства, продолжайте по
   `taxonomy/source-tiers.yaml` и фиксируйте пробел.

Например, для вопроса «Что означает параметр sign в API ВАТС?» корневая карта
указывает на `vpbx-api`. В [`maps/vpbx-api.toc.tsv`](maps/vpbx-api.toc.tsv)
находится строка «О параметре "sign"» с файлом `20-o-parametre-sign.md`, то есть
разделом
[`vpbx-api/sections/20-o-parametre-sign.md`](vpbx-api/sections/20-o-parametre-sign.md).
Откройте этот раздел и используйте его трассировку PDF, а не текст `hint`, как
основание ответа.

## Продуктовая разметка

`product_ids` в `index.md` и в картах ссылаются на
[`taxonomy/products.yaml#classes`](../../taxonomy/products.yaml). Весь раздел
наследует классы своего документа. Это **классы для маршрутизации поиска**, а
не привязка требования к Atomic Function. В текущем закрытом словаре нет
идентификаторов функций для разметки руководств на таком уровне. Если
документ охватывает несколько классов, карта оставляет оба кандидата и агент
уточняет релевантность по конкретному разделу.

## Обновление после новой версии руководства

Путь `docs/kb/<документ>/` остаётся постоянным. После замены извлечённых
`index.md` и `sections/` восстановите `product_ids` и
`product_taxonomy_ref` в frontmatter индекса, затем запустите:

```sh
python docs/kb/build_map.py
python docs/kb/build_map.py --check
python -m unittest discover -s tests -p 'test_kb_navigation.py'
```

Сборка читает существующие индексы, проверяет покрытие всех файлов разделов
и обновляет `MAP.json` вместе с `maps/*.json` и `maps/*.toc.tsv`. Скрипт не
извлекает PDF и не меняет содержание разделов. Проверка сообщает об устаревшей
карте или оглавлении, если изменились название, подсказка, путь или состав
разделов, и о лишнем файле в `maps/`. Тест навигации держит `MAP.json` и каждое
оглавление в пределах 32 768 Б: это ориентир одного чтения файла в чате.
