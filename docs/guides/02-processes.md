# Процессы P-01…P-10

| Процесс | Что делает | Навыки | Пример | MVP |
| --- | --- | --- | --- | --- |
| P-01 | Обрабатывает сессию выявления в A-CORE | нормализация, извлечение контекста, неоднозначности, сборка ядра | разобрать расшифровку встречи | да |
| P-02 | Управляет уточнениями | формирование и приоритизация вопросов, интеграция ответа | уточнить порог ожидания | да |
| P-03 | Формирует A-BCREQ | проблема, ценность, декомпозиция, сборка | оформить бизнес-требование | да |
| P-04 | Детализирует функциональные требования | не скомпилированы | получить A-FR | нет |
| P-05 | Собирает техническое задание | не скомпилированы | получить A-TZ | нет |
| P-06 | Моделирует сценарии | не скомпилированы | построить use case | нет |
| P-07 | Верифицирует требования | не скомпилированы | аудит документа | нет |
| P-08 | Оценивает тендерное ТЗ | не скомпилированы | gap-анализ тендера | нет |
| P-09 | Оценивает влияние изменения | не скомпилированы | найти затронутые требования | нет |
| P-10 | Ведёт жизненный цикл | не скомпилированы | собрать baseline и trace | нет |

Маршрут MVP выполняет P-01 → при необходимости P-02 → P-03. Запрос P-04…P-10
должен завершиться `out_of_slice`, а не выдуманным результатом.
