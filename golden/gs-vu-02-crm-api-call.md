# Эталон GS-VU-02: звонок по заявке, инициированный CRM через API

Синтетический эталон до подтверждения человеком применяется **только
структурно**: расхождение по структуре — отказ, расхождение по содержанию —
не отказ, иначе прогон воспроизводит эталон вместо решения задачи. Класс вне
среза маршрута (`in_slice: false`): эталон — данные для промптов спицы и
структурной сверки; `check_golden` проверяет его структуру наравне с эталонами
`contact-center` (`evaluation/validate-package.md`, пункты 2–8).

## Вход

`A-IN`, `raw`, один источник `SRC-01` — письмо руководителя отдела продаж:

> «Заявки с сайта лежат в CRM по полчаса, пока менеджер их заметит. Хотим,
> чтобы при новой заявке CRM сама набирала менеджера, а после его ответа —
> клиента. Делаем через API, отдельный интерфейс не нужен: всё в CRM. Если
> менеджер не ответит, пусть работает наша обычная переадресация на группу
> продаж.»

Реестр продуктов: маркер `А`, класс `voice-ucaas`, atomic function
`cpaas/function/programmable-voice-call`, профиль `P-API`, владелец —
руководитель отдела продаж.

Функция взята из каталога `taxonomy/mango-products.yaml`: программируемый
голосовой вызов (`params`: `from_number`, `callflow_id`); в её `classes` есть
`voice-ucaas`.

## Ожидаемая структура выхода

- Класс артефакта `A-BCREQ`, класс формата `F-SHORT`, проекция `V-BIZ`.
- Присутствуют все 14 слотов скелета.
- Пусты с причиной: `S-SETTINGS` («нет в источнике»), `S-UI` («нет по
  продукту» — профиль `P-API`), `S-NFR` («в источнике нет требований к
  качеству»).
- `S-INTEGRATION` заполнен (профиль `P-API`): CRM вызывает API Виртуальной АТС.
- `S-OPEN` несёт вопрос о номере, который увидит клиент: источник его не
  называет, а у функции есть параметр `from_number`.
- `S-GLOSSARY` содержит `Переадресация` — термин словаря
  `taxonomy/domain-glossary-voice-ucaas.yaml`: существующее правило АТС до
  ответа, на которое источник ссылается.
- `S-TRACE` непуст и связывает каждое требование `S-FR` с элементом ядра и
  `SRC-01`.

## Ожидаемое содержание (не проверяется машинно)

Проблема: время от заявки до звонка — до получаса. Решение на языке бизнеса —
звонок по заявке начинается автоматически, сначала менеджеру, затем клиенту.
Поведение при неответе менеджера не меняется: действует текущее правило
переадресации.

## Чего в эталоне намеренно нет

- Описания запросов API: `A-BCREQ` отвечает на «зачем» и «что», а не на «как».
- Подмены `Переадресация` на `Перевод звонка`: при неответе менеджера разговора
  нет, вызов направляет правило АТС.
- Утверждения о доступности функции клиенту: каталог её не устанавливает
  (`availability: not-established-by-taxonomy`).
