# Эталон GS-AR-01: ежемесячный ROMI по рекламным каналам

Синтетический эталон до подтверждения человеком применяется **только
структурно**: расхождение по структуре — отказ, расхождение по содержанию —
не отказ, иначе прогон воспроизводит эталон вместо решения задачи. Класс вне
среза маршрута (`in_slice: false`): эталон — данные для промптов спицы и
структурной сверки, `check_golden` его не читает.

## Вход

`A-IN`, `raw`, один источник `SRC-01` — расшифровка встречи с директором по
маркетингу:

> «Каждый месяц мы вручную сводим расходы на рекламу и выручку из CRM, чтобы
> понять, какой канал окупается. Это два дня работы аналитика. Хотим видеть
> ROMI по каждому каналу за месяц без ручной сводки: расходы из рекламных
> кабинетов, выручка по сделкам из CRM.»

Реестр продуктов: маркер `А`, класс `analytics-reporting`, atomic function
`end-to-end-analytics/function/romi-calculation`, профиль `P-NO-SETTINGS`,
владелец — директор по маркетингу.

Функция взята из каталога `taxonomy/mango-products.yaml`: расчёт ROMI
(`params`: `cost_source`, `revenue_source`). Профиль совпадает с профилем
класса по умолчанию (`taxonomy/products.yaml`).

## Ожидаемая структура выхода

- Класс артефакта `A-BCREQ`, класс формата `F-SHORT`, проекция `V-BIZ`.
- Присутствуют все 14 слотов скелета.
- Пусты с причиной: `S-SETTINGS` («нет по продукту»), `S-UI` («нет в
  источнике»), `S-NFR` («в источнике нет требований к качеству»).
- `S-INTEGRATION` заполнен: источники расходов и выручки — внешние системы.
- `S-GLOSSARY` содержит `Сквозная аналитика` — термин словаря
  `taxonomy/domain-glossary-analytics-reporting.yaml`.
- `S-TRACE` непуст и связывает каждое требование `S-FR` с элементом ядра и
  `SRC-01`.

## Ожидаемое содержание (не проверяется машинно)

Проблема: окупаемость каналов считается вручную, два дня работы аналитика в
месяц. Гипотеза ценности: автоматический ROMI по каналу снимает ручную сводку.
Предмет — окупаемость с учётом выручки (сквозная аналитика), а не только
источник звонка.

## Чего в эталоне намеренно нет

- Подмены `Сквозная аналитика` на `Коллтрекинг`: источник называет выручку из
  CRM, без неё ROMI не считается.
- Модели атрибуции: источник её не выбирает; если она нужна для расчёта, это
  открытый вопрос в `S-OPEN`, а не решение.
- Утверждения о доступности функции клиенту: каталог её не устанавливает
  (`availability: not-established-by-taxonomy`).
